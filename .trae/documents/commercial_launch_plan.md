# 独立开发者应用商业化上线计划 (Activity Assistant)

作为一个独立开发者，要将应用打造成成熟的商业产品，除了核心功能外，还需要关注用户体验的稳定性、数据驱动的运营决策以及合规性。以下是针对 Activity Assistant 的商业化上线计划。

## 阶段一：核心体验增强 (Robustness & Offline First)
目标：确保应用在各种网络环境下（弱网、无网）都能稳定运行，不丢失用户数据。

### 1. 全局网络状态管理
- [ ] **状态监听**: 在 `App.uvue` 中初始化 `uni.onNetworkStatusChange`，实时监控网络连接状态。
- [ ] **全局提示**: 当网络断开时，在应用顶部显示“网络已断开，正在使用离线模式”的优雅提示（Toast 或顶部通告栏）。
- [ ] **状态共享**: 将网络状态存储在 `store` 中，供所有页面和业务逻辑访问。

### 2. 数据持久化与离线支持
- [ ] **本地缓存 (Local Storage)**:
    - 修改 `store/index.uts`，在获取活动列表、用户信息成功后，使用 `uni.setStorageSync` 备份数据。
    - 应用启动时，优先从 `uni.getStorageSync` 加载缓存数据，实现“秒开”体验，然后再尝试网络请求更新数据。
- [ ] **离线操作队列 (Offline Queue)**:
    - 创建 `OfflineSyncManager`。
    - 当用户在离线状态下创建活动或签到时，将操作（Action, Payload, Timestamp）存入本地队列。
    - 网络恢复时，自动遍历队列并同步到服务器。

### 3. 健壮的错误处理
- [ ] **统一请求拦截**:
    - 改造 `utils/request.uts`，增加请求拦截器。
    - 统一处理 HTTP 401 (未登录)、500 (服务器错误)、Timeout (超时) 等情况。
    - 针对不同错误给出用户友好的提示（如“服务器开小差了”而不是“500 Internal Server Error”）。
- [ ] **UI 降级**:
    - 图片加载失败时显示默认占位图。
    - 列表加载失败时显示“重试”按钮。

## 阶段二：数据分析与埋点 (User Behavior Analytics)
目标：了解用户如何使用产品，为产品迭代和商业化决策提供数据支持。

### 1. 隐私优先的埋点系统
- [ ] **设计埋点事件表**:
    - 核心转化：`app_launch` (启动), `activity_create` (创建活动), `checkin_success` (签到成功), `share_click` (点击分享).
    - 错误监控：`api_error` (接口报错), `crash_log` (崩溃日志).
- [ ] **实现简易分析服务**:
    - 创建 `utils/analytics.uts`。
    - 实现 `logEvent(eventName, params)` 方法。
    - 策略：先存本地，批量或定时上传到后端 `/api/analytics` 接口，避免消耗过多流量。

### 2. 用户反馈闭环
- [ ] **意见反馈入口**: 在“我的”页面增加“帮助与反馈”功能。
- [ ] **联系方式**: 提供开发者邮箱或即时通讯群组链接。

## 阶段三：商业化与合规 (Monetization & Compliance)
目标：确保应用符合上架要求并具备盈利潜力。

### 1. 合规性准备
- [ ] **隐私政策与用户协议**:
    - 生成并展示《隐私政策》和《用户协议》，明确数据收集用途（特别是埋点数据）。
    - 首次启动时的弹窗同意流程。
- [ ] **注销功能**: 必须提供显眼的账号注销入口（App Store 强制要求）。

### 2. 应用商店优化 (ASO)
- [ ] **截图与预览视频**: 制作精美的 App Store / 应用宝 截图。
- [ ] **关键词优化**: 标题、副标题、描述覆盖核心关键词（活动、签到、组织、管理）。

### 3. 盈利模式探索（后续规划）
- [ ] **高级版功能**: 如导出 Excel 报表、短信通知参与者、多管理员协作等。
- [ ] **广告接入**: 在非核心流程（如活动结束页）接入开屏或 Banner 广告。

## 执行路线图 (Roadmap)

1. **Step 1 (当前重点)**: 完成 **阶段一** 的网络监控和本地持久化，保证基础体验。
2. **Step 2**: 完成 **阶段二** 的埋点系统，上线前必须跑通。
3. **Step 3**: 完善 **阶段三** 的合规文档，准备提交审核。

## 立即执行任务 (Action Items)

1. 修改 `App.uvue` 添加网络监听。
2. 改造 `store/index.uts` 实现数据持久化。
3. 封装 `utils/analytics.uts` 埋点工具。
