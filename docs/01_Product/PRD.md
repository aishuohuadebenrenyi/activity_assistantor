## 2. 产品概述

**活动帮手** 是面向活动组织者的移动端活动管理应用，聚焦"创建活动—管理报名—签到跟进—结果沉淀"闭环，帮助用户在手机端完成活动全流程管理。

### 2.1 产品定位

- **目标用户**：社区运营、企业行政/HR、培训负责人、社群组织者。
- **核心价值**：快速发起、过程可控、数据可见。
- **产品形态**：轻量级移动应用，强调低学习成本与高频操作效率。

## 3. 页面与交互设计

### 3.1 全局导航结构
- 底部 TabBar 三个主入口：**首页**、**创建**、**我的**。
- 非 Tab 页（如详情、报名人员、分享、编辑资料）采用页面内跳转返回。
- 全局背景与导航栏风格统一，提升页面过渡连贯性。

### 3.2 首页（活动列表）
- 顶部展示活动统计卡片，列表区展示活动项。
- 搜索区为**折叠式入口**：点击列表头部搜索按钮后展开“搜索 + 状态筛选”。
- 列表支持按状态筛选（全部/进行中/即将开始/已结束）与关键词检索（名称/地点）。
- 提供“新建”快捷入口与空状态引导按钮。
- TabBar 支持滚动联动显隐；在搜索区展开时保持 TabBar 可见以避免交互抖动。

### 3.3 创建页
- 表单覆盖名称、类型、日期、时间、地点、人数上限、活动介绍。
- 支持键盘高度监听与底部动态避让，避免输入时遮挡提交区域。
- 提交按钮文案为 **“立即创建活动”**，支持提交状态保护，避免重复提交。

### 3.4 活动详情页
- 分为“活动统计”“活动详情摘要”“详细信息表单”“活动工具”四个区域。
- “详细信息”区域支持折叠与编辑，编辑入口位于**详细信息模块头部右上角**。
- 工具区提供“报名情况”“分享”快捷操作。
- 对无效活动 ID 提供异常态提示和返回首页入口。

### 3.5 报名人员页
- 顶部展示报名统计（报名人数、已签到、未签到、签到率）。
- “报名人员”模块支持搜索、筛选、签到状态切换。
- **导出入口位于报名人员模块头部右侧**，当前为占位能力（提示开发中）。

### 3.6 我的页与资料页
- 我的页展示个人数据看板与通用设置入口（主题、通知、帮助等）。
- 编辑资料页支持修改基础信息、退出登录与注销账号。

### 3.7 组织与订阅管理 (新增)
- **组织模型**：支持个人组织者升级为“组织”实体，支持多管理员协同。
- **订阅计划**：提供基础版、专业版、企业版套餐，对应不同的权益（如报名人数上限、导出频次等）。

### 3.8 埋点与分析 (新增)
- **行为追踪**：记录用户从浏览详情、点击报名到核销的全链路行为。
- **多维看板**：提供漏斗转化、日活趋势、地域分布等核心运营指标。

### 3.9 客服与支持 (新增)
- **智能客服**：集成客服入口，支持上下文 Token 传递以提高问题解决效率。
- **反馈闭环**：用户反馈直接同步至后端管理系统。

## 4. 关键体验原则

- **信息密度平衡**：通过卡片分区承载统计、内容与工具，降低认知负担。
- **关键动作前置**：创建、编辑、导出等操作放在对应模块头部，提升可发现性。
- **状态清晰反馈**：点击态、空态、异常态、保存成功提示保持一致。
- **安全区适配**：底部内容避让系统安全区与键盘，保证可见可点。

## 5. 当前版本范围

- **已实现**：
    - **角色化路由**：通过 `pages.json` 条件编译实现 App 端（管理）与小程序端（参与）的自动切换。
    - **活动全生命周期**：创建、编辑同步、删除、详情展示（含统计看板）。
    - **报名与签到**：
        - 小程序端：在线报名、查看电子票、扫码自助签到。
        - App 端：扫码核销、手动签到、报名名单管理。
    - **数据导出**：支持将报名名单以 CSV 格式发送至指定邮箱。
    - **离线能力**：支持断网下执行关键操作，并在恢复后自动同步至后端。
    - **内容安全**：集成微信 SecCheck，自动拦截违规活动内容。
    - **举报功能**：符合合规要求的活动举报机制。
- **配置与调试**：
    - **全局 Mock**：一键切换模拟数据与真实 API。
    - **鉴权体系**：JWT 登录闭环（含微信授权与短信验证码）。

## 6. 多端差异化设计 (Multi-platform Strategy)

基于“App做管理，小程序做参与”的原则，两端在功能和交互上存在显著差异。

### 6.1 角色分工
| 维度 | App 端 (Android/iOS) | 微信小程序端 |
| :--- | :--- | :--- |
| **核心角色** | 主办方 / 管理员 | 参与者 / 用户 |
| **核心功能** | 创建活动、管理报名、扫码/手动核销、导出数据 | 浏览活动、在线报名、查看电子票、扫码签到 |
| **首页视图** | 活动管理列表 (Dashboard) | 我的报名列表 (Ticket Wallet) |
| **离线支持** | 强 (支持管理操作队列) | 弱 (仅支持基础缓存展示) |

## 10. 商家运营指南：如何利用数据驱动增长

为了帮助商家（活动组织者）更好地理解活动效果并优化后续活动，本产品内置了多维度的数据分析能力。以下是如何解读和使用这些数据的指南。

### 9.1 核心数据指标解读

在“我的”页面和“活动详情”页，您可以看到以下关键指标：

| 指标名称 | 定义 | 商业价值 | 建议行动 |
| :--- | :--- | :--- | :--- |
| **浏览量 (Views)** | 活动详情页被打开的次数 | 衡量活动标题/海报的吸引力 | 若浏览量低，优化活动标题或分享渠道；若浏览量高但报名少，优化详情页描述。 |
| **报名人数 (Registrations)** | 成功提交报名信息的人数 | 衡量活动的市场需求 | 关注报名增长趋势，若前期增长缓慢，需加大推广力度。 |
| **签到率 (Check-in Rate)** | 实际签到人数 / 报名人数 | 衡量用户的履约意愿和活动质量 | 若签到率低于 60%，建议在活动前发送短信/电话提醒，或设置“签到有礼”环节。 |
| **转化漏斗** | 浏览 -> 报名 -> 签到 | 识别用户流失环节 | 计算各环节转化率，找出短板（如：浏览1000，报名10，说明详情页转化极差）。 |

### 9.2 如何使用数据报表

1.  **活动复盘**：
    *   每次活动结束后，打开“活动详情页”，截图保存统计卡片。
    *   对比不同类型（如：线上 vs 线下，培训 vs 聚会）活动的签到率，找出最受用户欢迎的活动形式。
2.  **用户分层**：
    *   通过“报名人员”列表，识别出“频繁报名且从不缺席”的忠实用户，给予VIP待遇或邀请其担任志愿者。
    *   对于“频繁报名但经常缺席”的用户，建立黑名单或限制其报名热门活动。
3.  **最佳发布时间**：
    *   观察不同时间段发布活动的浏览量增长曲线（需结合后台埋点数据），找到用户最活跃的时间点（如周二上午或周五下午）进行发布。

### 9.3 常见问题排查

*   **数据不更新？**
    *   检查网络连接，App 会在网络恢复后自动同步离线数据。
    *   尝试下拉刷新列表页。
*   **签到人数不对？**
    *   确认是否有多位管理员同时签到，系统支持多端并发，但在弱网环境下可能会有短暂延迟。
