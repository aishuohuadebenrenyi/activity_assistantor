# 文档版本管理机制

为了确保项目文档与源代码实现保持高度同步，特制定本版本管理机制。

## 1. 版本命名规范

版本号采用 `v[主版本].[次版本].[修订号]` 格式：
- **主版本 (Major)**：项目重大重构、架构调整或核心业务逻辑变更。
- **次版本 (Minor)**：新增功能模块、API 接口扩展或数据库表结构新增。
- **修订号 (Patch)**：文档错误修正、细节描述完善或注释更新。

## 2. 版本记录表要求

所有核心技术文档（PRD、API Reference、Database Design 等）必须在文末或文首包含“版本修订记录”表，包含以下字段：

| 版本号 | 修订日期 | 修订人 | 修订内容说明 | 对应代码版本 |
| :--- | :--- | :--- | :--- | :--- |
| v6.2.0 | 2026-03-15 | AI Assistant | 全面梳理 API、数据库及功能模块，同步最新实现 | v6.2.0-stable |

## 3. 同步触发机制

当发生以下变更时，必须同步更新相关文档：
1. **API 变更**：新增接口、修改参数或调整返回格式 -> 更新 `API_Reference.md`。
2. **模型变更**：新增数据库表、修改字段属性或调整表间关系 -> 更新 `Database_Design.md`。
3. **功能逻辑变更**：新增业务模块、调整操作流程或引入新算法 -> 更新 `PRD.md` 和 `Tech_Specs.md`。
4. **架构调整**：引入中间件、改变数据流向或优化底层适配 -> 更新 `Architecture.md`。

## 4. 维护责任

- **开发者**：在提交代码变更的同时，负责更新对应的技术文档。
- **代码审查 (Code Review)**：文档同步情况应作为 CR 的必要检查项。
