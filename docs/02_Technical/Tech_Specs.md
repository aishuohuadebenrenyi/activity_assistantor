## 2. 技术稳健性 (Robustness)

**目标：确保应用在各种极端情况下依然可用，不崩溃、不丢数据。**

### 1.1 网络状态与离线优先 (Offline First)
- **网络状态监控**：
  - [ ] 实时监听网络切换（WiFi <-> 4G <-> 无网），并自动重试失败请求。
  - [ ] **UI 反馈**：无网时顶部显示温和提示条，避免全屏错误页阻断操作。
- **本地数据持久化**：
  - [ ] **缓存策略**：所有列表页优先展示本地缓存，后台静默刷新（Stale-while-revalidate）。
  - [ ] **离线操作队列**：用户在离线时的创建、编辑、点赞等操作存入队列，网络恢复后自动同步。
  - [ ] **图片缓存**：使用合适的图片缓存策略，减少重复流量消耗。

### 1.2 异常处理与降级 (Error Handling)
- **全局错误拦截**：
  - [ ] 统一处理 HTTP 401（登录过期自动刷新 Token 或跳转登录页）。
  - [ ] 统一处理 HTTP 500/502（服务器故障提示“服务稍候回来”）。
- **崩溃防护**：
  - [ ] 接入崩溃上报工具（如 Sentry, Bugly），第一时间捕获闪退堆栈。
  - [ ] 关键流程增加 `try-catch` 兜底，防止单一模块报错导致 App 白屏。

### 1.3 性能优化 (Performance)
- **启动速度**：优化首屏渲染时间（FCP），控制包体积（分包加载）。
- **内存管理**：长列表使用虚拟列表组件，及时释放大图资源。
- **电量消耗**：避免后台频繁定位或高频轮询。

## 2. DevOps 与维护 (Maintenance)

**目标：提高开发效率，保证代码质量。**

### 2.1 版本控制
- **Git 规范**：使用 Semantic Versioning (v1.0.0)，Commit 信息清晰。
- **分支管理**：Main (稳定), Develop (开发), Feature/xxx (特性)。

### 2.2 持续集成/部署 (CI/CD)
- **自动化构建**：使用 GitHub Actions 或 Jenkins 自动打包。
- **热更新 (Hotfix)**：利用 uni-app 的 wgt 资源包更新机制，快速修复线上 Bug，无需重新审核。
