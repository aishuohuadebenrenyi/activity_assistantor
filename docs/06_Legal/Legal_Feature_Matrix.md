# 条款必须覆盖的功能清单（以当前代码为准）

本文用于将“产品实际功能与数据流”映射到隐私政策/用户协议/内容治理等条款的必备覆盖点，避免出现“模板条款与实际不符”导致的审核或投诉风险。

## 覆盖范围

- 客户端：App（主办方侧）与微信小程序（参与者侧）
- 以现有页面与接口调用为依据：登录/报名/签到核销/分享/举报/反馈/账号注销等

## 1. 功能-数据-接口映射

| 功能/页面 | 主要用户角色 | 主要个人信息/内容 | 客户端权限/系统能力 | 前端接口 | 服务端存储/处理要点 |
|---|---|---|---|---|---|
| 登录（手机号验证码） | App、小程序 | 手机号、验证码（仅用于验证） | 打开外链（查看协议） | `POST /auth/login` | 用户表保存手机号等；JWT token 有效期 7 天（服务端不落库） |
| 登录（微信一键登录） | 小程序 | 微信端返回的 `code`（用于换取 openid/手机号） | 微信登录能力 | `POST /auth/login/wechat` | 服务端通过微信接口换取 openid；用户表保存 openid（可空） |
| 发送验证码 | App | 手机号 | 无 | `POST /auth/send-code`（前端当前为模拟发送） | 服务端内存缓存验证码与限频信息（进程重启会丢失） |
| 活动创建/编辑/删除 | App（主办方） | 活动名称/类型/时间/地点/描述（可能包含个人信息/敏感内容） | 无 | `POST/PUT/DELETE /activities` | 活动表存储；服务端在创建/更新时做内容安全检测（第三方微信接口） |
| 活动列表浏览 | App、小程序 | 浏览行为（当前仅本地日志） | 网络访问 | `GET /activities` | 活动表读取；浏览量字段存在（views_count） |
| 活动报名 | 小程序（参与者） | 报名姓名、报名手机号 | 无 | `POST /activities/{id}/register` | 报名表存储姓名/手机号；同活动按手机号去重 |
| 报名凭证/电子票 | 小程序 | 报名记录、签到码（ticket_code） | 生成二维码图片（第三方服务）/拨打电话/（拟）地图导航 | `GET /activities/{id}/my-ticket` | 服务端生成签到码并返回；客户端将签到码发给第三方二维码生成服务用于渲染图片 |
| 签到核销（组织者扫码） | App（主办方） | 扫码结果（签到码内容）/报名记录标识 | 相机（扫码） | `POST /activities/{id}/checkin`（`qr_data`） | 核销记录表存储签到时间；一条报名只允许一条核销记录 |
| 签到核销（手动） | App（主办方） | `registration_id` | 无 | `POST /participants/{activityId}/checkin`（`registration_id`） | 同上 |
| 报名名单导出 | App（主办方） | 报名姓名/手机号、收件邮箱 | 无 | `POST /activities/{id}/export` | 服务端生成 CSV（含明文手机号）并“模拟发邮件”（未接入真实邮件服务） |
| 分享活动 | App（主办方） | 分享链接/小程序码（二维码数据） | 写入剪贴板；（拟）保存到相册 | `GET /activities/{id}/share` | 服务端通过微信接口生成 URL Link 与小程序码（第三方处理） |
| 举报活动 | 小程序（参与者） | 举报原因（枚举）、被举报活动 ID、举报人 ID | ActionSheet 选择 | `POST /activities/{id}/report` | 举报表存储 reason/detail/status 等 |
| 意见反馈 | App、小程序 | 反馈内容（最多 500 字）、联系方式（选填） | 无 | `POST /feedback` | 当前后端未实现该路由（真实后端模式下将失败）；Mock 模式可用 |
| 账号退出登录 | App、小程序 | 无（清除/重置登录态） | 无 | 无 | 客户端跳转登录页；token 仍可能留在本地存储，需条款声明本地缓存机制 |
| 账号注销（含冷静期提示） | App、小程序 | 账号标识（用户 ID/手机号/openid）、历史活动与报名记录 | 无 | `DELETE /user/account`（含 `force` 语义） | 服务端支持 pending_deletion 状态与“二次确认”最终注销；并对用户信息做匿名化/脱敏处理 |

## 2. 本地存储与离线能力（条款需披露）

| 存储项 | Key | 内容 | 目的 |
|---|---|---|---|
| 活动列表缓存 | `activities_data` | 活动列表与相关统计 | 提升加载速度、离线可用 |
| 用户信息缓存 | `user_data` | 用户基本信息 + token | 维持登录状态、请求鉴权 |
| 离线请求队列 | `offline_request_queue` | 非 GET 请求的离线待同步队列 | 网络恢复后自动同步 |
| 其它 | `token`（清理用） | 历史兼容键 | 注销时清理 |

## 3. 终端权限/系统能力（条款与系统权限弹窗需一致）

- 相机：用于扫码签到/核销
- 相册读取/写入（iOS 权限声明已配置）：用于选择并上传活动封面、保存二维码图片（部分能力目前为占位实现）
- 位置（微信小程序与 iOS 权限声明已配置）：用于查找附近活动/导航（当前页面调用以“模拟”为主，条款应写为“在您授权后用于导航或展示地点”等保守表述）
- 剪贴板：复制分享链接
- 拨打电话：联系主办方（当前为示例号码，生产需对齐真实逻辑）

## 4. 第三方处理/共享点（条款需列示）

- 微信开放平台接口（服务端调用）：换取 openid、生成 URL Link、小程序码、内容安全检测
- 二维码生成服务（客户端调用）：报名凭证页使用第三方生成二维码图片（将 ticket_code 作为参数用于生成图片）
- 短信服务（计划接入）：当前实现为模拟发送；上线通常需要接入第三方短信服务商
- 邮件服务（计划接入）：报名导出当前为模拟发送；上线通常需要接入第三方邮件服务商

## 5. 必须在协议中出现的“产品承诺点”

- 用户可通过举报入口反馈违规活动内容；平台会按规则处理
- 用户可申请注销账号；冷静期与最终注销/匿名化处理规则需明确
- 报名/签到/导出涉及手机号等个人信息；主办方对导出数据负有保密与合规使用义务
- 发生争议（活动纠纷、诈骗等）时，为满足法律义务或维权需要，可能保留必要记录并做最小化处理
