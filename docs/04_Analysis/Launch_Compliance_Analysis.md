# iOS App Store 上架与微信小程序上线合规性分析报告

## 1. 概述
本报告针对 Activity Assistant (uni-app x 开发) 项目，分析将其上架至 iOS App Store 及发布至微信小程序平台时，所需注意的合规性问题、技术适配点及运营规则。

## 2. iOS App Store 上架注意事项

### 2.1 隐私与数据合规 (Privacy)
*   **隐私政策 (Privacy Policy)**: App Store Connect 中必须提交有效的隐私政策 URL。政策中必须明确说明收集的数据类型（如：联系方式、位置、用户内容）、用途及是否与第三方共享。
*   **权限申请描述 (Info.plist)**:
    *   **相机权限 (`NSCameraUsageDescription`)**: 项目中使用了扫码功能，必须在 `manifest.json` -> `app-plus` -> `distribute` -> `ios` -> `privacyDescription` 中添加描述，例如：“App需要访问您的相机以扫描二维码进行活动签到。”
    *   **位置/相册/麦克风**: 如果未来启用相关功能，同样需要添加描述。描述必须具体，不能模糊（如“我们需要权限以提供服务”会被拒）。
*   **账号注销 (Account Deletion)**: App Store 审核指南 (Guideline 5.1.1(v)) 要求：如果 App 允许用户创建账号，则**必须**在 App 内提供删除账号的选项。该功能必须是容易发现的，且能彻底删除服务器上的用户数据。

### 2.2 用户生成内容 (UGC) 管控
*   **定义**: 本 App 允许用户“创建活动”（输入标题、描述、上传图片），属于 UGC 类应用。
*   **审核要求 (Guideline 1.2)**:
    *   **内容过滤**: 必须有机制过滤令人反感的内容（敏感词过滤）。
    *   **举报机制**: 必须允许用户举报违规活动或内容。
    *   **封禁机制**: 必须有能力屏蔽违规用户。
    *   **EULA**: 用户必须同意“最终用户许可协议”，声明对违规内容零容忍。
*   **现状风险**: 当前项目缺乏举报按钮和自动内容审核 API，这是**拒审的高风险点**。

### 2.3 支付与商业模式 (Payments)
*   **虚拟 vs 实物**:
    *   如果活动报名费被视为**虚拟服务**（如线上课程、会员），**必须**使用 Apple In-App Purchase (IAP)，且 Apple 抽取 15%-30% 分成。
    *   如果活动是**线下实体活动**（如线下聚会、展会门票），可以使用微信/支付宝等第三方支付 (Guideline 3.1.3(e))。
*   **建议**: 明确界定活动性质。若为线下活动，需在审核备注中向 Apple 说明，证明其为线下服务。

### 2.4 登录方式 (Sign in with Apple)
*   **强制要求 (Guideline 4.8)**: 如果 App 提供了第三方登录（如微信登录、手机号一键登录），则**必须**同时提供“通过 Apple 登录 (Sign in with Apple)”。
*   **适配**: 需在登录页添加 Apple 登录按钮，并处理相关逻辑。

## 3. 微信小程序上线注意事项

### 3.1 平台类目与资质
*   **类目选择**: “活动管理”可能涉及【社交-笔记】、【工具-信息查询】或【生活服务-线下活动】。
*   **风险**: 若被判定为【社交】类目，可能需要《增值电信业务经营许可证》或《互联网信息服务安全评估》。建议初期尝试以【工具】或【生活服务】类目提交，强调其工具属性（签到、管理）。

### 3.2 内容安全 (Content Security)
*   **强制接入**: 微信小程序**强制**要求接入内容安全 API (`security.msgSecCheck` 和 `security.imgSecCheck`)。
*   **拦截**: 用户提交活动标题、描述时，必须调用微信 API 进行校验，否则无法过审，甚至可能导致小程序被封禁。
*   **现状**: 后端需集成微信内容安全接口。

### 3.3 iOS 虚拟支付限制
*   **规则**: 在 iOS 端的小程序中，**严禁**提供虚拟物品的购买支付（如知识付费、会员）。
*   **适配**:
    *   如果是线下活动门票，通常允许支付。
    *   如果是线上虚拟活动，iOS 端需隐藏支付按钮，提示“请在安卓设备或网页端购买”。

### 3.4 用户隐私与授权
*   **隐私协议**: 必须在小程序后台设置《用户隐私保护指引》，明确收集“手机号”、“用户信息”的用途。
*   **按需授权**: 不能在小程序启动时直接弹出授权框。必须在用户点击“登录”或“报名”等具体操作时才触发授权。
*   **手机号获取**: `getPhoneNumber` 目前是收费接口（按次收费，有免费额度），需注意成本。

## 4. 技术适配与测试清单

### 4.1 iOS 适配
*   **Safe Area**: 检查 iPhone 刘海屏、灵动岛区域的布局适配（uni-app x 通常会自动处理，但需检查自定义导航栏）。
*   **IPv6**: App Store 要求服务器必须支持 IPv6 网络访问。
*   **UIWebView**: 确保未使用已被废弃的 `UIWebView` API（uni-app x 使用原生渲染或 WKWebView，通常无此问题，但需注意第三方 SDK）。

### 4.2 微信小程序适配
*   **包体积**: 主包不能超过 2MB。建议将静态资源（大图）放入 CDN，或使用分包加载。
*   **HTTPS**: 所有网络请求（API、图片）必须使用 HTTPS，且域名需在小程序后台配置白名单。
