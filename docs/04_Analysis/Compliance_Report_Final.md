# 活动帮手 (Activity Assistant) 上架合规性整改报告 (v6.1 最终版)

## 1. 报告摘要
本报告详述了“活动帮手”项目在 iOS App Store、微信小程序及后端云服务方面的合规性现状及整改完成情况。本项目已完成核心合规项（如账号注销、隐私政策、内容安全）的整改，符合相关法律法规及平台政策要求。

## 2. 合规性整改项清单与法规依据

### 2.1 用户权利与账号安全
| 检查项 | 法规/政策依据 | 整改现状 | 验收指标 |
| :--- | :--- | :--- | :--- |
| **账号注销功能** | 《个人信息保护法》第15/47条；App Store 指南 5.1.1(v) | **已完成**：前端提供注销入口，后端实现数据永久删除。 | 用户点击注销后，账号及关联活动、报名数据立即在数据库中删除。 |
| **强制隐私同意** | 《App违法违规收集使用个人信息行为认定方法》 | **已完成**：登录页增加强制勾选框。 | 未勾选协议时，登录/注册按钮置灰或弹出强制提示。 |
| **Apple 登录** | App Store 指南 4.8 | **已完成**：iOS 端集成 Sign in with Apple。 | iOS 审核版本中，Apple 登录按钮可见且逻辑跑通。 |

### 2.2 内容安全与 UGC 管控 (App Store 1.2 / 微信小程序强制要求)
| 检查项 | 整改措施 | 验收指标 |
| :--- | :--- | :--- |
| **违规内容过滤** | 集成微信 `msg_sec_check` API。 | 创建活动标题包含敏感词时，返回 400 错误并提示用户。 |
| **举报与申诉** | 活动详情页增加“举报”按钮。 | 举报信息实时存入后端 `reports` 表并进入人工审核队列。 |
| **脱敏显示** | 报名列表对手机号进行 `138****5678` 处理。 | 非活动组织者无法查看参与者的完整手机号。 |

### 2.3 后端安全与部署合规
| 检查项 | 平台要求 | 实现详情 |
| :--- | :--- | :--- |
| **HTTPS 加密** | App Store / 微信小程序强制要求 | 阿里云配置 SSL 证书，全站强制 443 转发，后端使用 `Flask-Talisman` 加固。 |
| **频率限制** | 基础安全防护 | 引入 `Flask-Limiter`，默认限制每小时 50 次请求，防止暴力破解。 |
| **数据加密** | 《数据安全法》 | 数据库敏感字段加密存储，Token 采用 JWT 256 位加密。 |

### 4.2 隐私政策核心条款摘要
- **数据收集**：仅收集必要的手机号用于登录，位置信息仅用于活动导航（需用户授权）。
- **数据共享**：除微信登录/分享外，不与任何第三方共享用户信息。
- **用户权利**：支持随时查看、更正及永久删除（注销）个人信息。

## 5. 整改验证与风险降级

### 5.1 复测方法
1. **黑盒测试**：尝试在创建活动时输入政治敏感词，验证是否拦截。
2. **安全扫描**：使用 Nmap 或 OWASP ZAP 扫描后端接口，验证是否有未加密传输。
3. **流程复核**：模拟用户注销，验证数据库中 `users`、`activities` 对应 ID 是否确实删除。

### 5.2 风险降级规则
- **高风险 (P0)**：违反平台红线（如无注销功能），必须上线前解决。
- **中风险 (P1)**：优化类项（如脱敏不够彻底），可随下个版本迭代。
- **低风险 (P2)**：建议项（如 UI 微调），不影响上架审核。

## 6. 结论
经过本次系统性整改，“活动帮手”已扫清主要合规障碍。建议运营团队在正式提交审核前，务必确保 **ICP 备案域名** 处于生效状态，且 **隐私协议 URL** 能够正常外网访问。
